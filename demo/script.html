1. The problem

Show the top of the demo page.

A brand today runs five to ten AI tools. Ad copy, support, email, product pages.

They all need the same facts. The live promo code. The shipping threshold. The hero product.

Right now each tool either re-reads the whole Slack history every time, or it quotes a value that was replaced weeks ago.

2. Tech stack

Scroll to the four steps, then to the terminal output.

Brand Brain is a fact ledger.

NVIDIA Nemotron on Fireworks reads the log and pulls out decisions.

DeepSeek on Fireworks checks each one. Is this a real decision, or a proposal, a question, or someone remembering an old value?

Verified facts go into a SQLite store with a start date and an end date.

A question becomes one small model call and a SQL lookup.

Fireworks serverless made this possible. Both models run in under a second for a fraction of a cent, so we can afford to verify every single message.

Here is the output. The promo code is FALL30. It took effect on 17 October. Here is the source message. It replaced VIP15.

3. Benchmark

Scroll to the table.

The baseline is Claude Opus 5.5 reading the full log, with the same prompt.

120 held-out questions. The test seed comes from our code-freeze commit, so we could not tune on it.

Opus scores 100 percent.

DeepSeek reading the full log scores 83.

Brand Brain on open models scores 79.

At one 160th of the cost per correct answer. 43 times fewer tokens. 10 times faster.

And it beats DeepSeek with the full log on two-hop questions, 14 to 10, because the second hop runs in code.

Our first version scored 27 percent. The verify step took it to 79. That one change is the whole lesson: memory is deciding what counts as a fact.

We do not beat Opus on accuracy. We say so in the README. Everything reproduces with one command.
